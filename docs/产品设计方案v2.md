## 1. 一句话

项目方把赏金和"什么算被攻破"一起锁进链上程序；白帽把攻击交易**私密**提交，交易只在 Chainlink CRE 机密工作流（TEE）里被模拟，**从不广播、从不公开**；模拟证明不变量被打破后，链上程序在同一笔交易里**暂停金库并把赏金打给白帽**。金库里的钱一分没少。

## 2. 为什么必须上链（评委必问）

- **项目方不用被信任**：赏金事先锁在程序账户里，规则公开，兑付由程序执行。撤回赏金要先申请、等 7 天，所以项目方没法在看到报告后抢先撤走。
- **白帽不用被信任**：他不需要真的攻击、转走资金再谈判，只提交一笔"能把金库掏空"的交易给飞地模拟。
- **暂停和赔付原子发生**：同一笔 `on_report` 交易里完成，中间没人能插手。
- 普通 web2 后端做不到"不信任任何一方还能自动兑付"。

## 3. 产品形态

双边市场 + 一层自动验证：

- **项目方（Protocol）**：给自己的程序挂赏金、定义不变量、锁入 SOL。唯一的集成成本是程序里有一个 `guardian` 字段和一条只允许 guardian 调用的 `pause` 指令，guardian 设成赏金 PDA。
- **白帽（Whitehat）**：发现漏洞后私密提交攻击交易，验证通过自动拿钱。
- **验证层**：CRE 机密工作流在 TEE 里读模拟前余额、模拟攻击交易、读模拟后余额，判断 `pre >= 阈值 && post < 阈值`，输出 96 字节的签名报告。报告里只有数字和地址，没有攻击交易。

MVP 只演示一个被保护的金库（队友的赏金程序目前用固定种子 `["bounty"]`，一次部署只有一个赏金）。多项目市场是路线图。

### 3.1 面向谁

两边都要，但分量不同：

- **付钱的是项目方**：赏金、抽成、监控订阅都由项目方出，商业模式靠他们成立。但项目方在产品里的动作很少：接入一次暂停钩子、注册一次赏金，之后基本只看"有没有人领走"。接入本身是开发者在合约和 CLI 里完成的，网页只负责展示和引导。
- **天天用网页的是白帽**：浏览赏金、私密提交、看验证过程、拿钱，全部发生在网页上。CRE 的价值也全在这条链路里（Chainlink 评分里 CRE 用法占 40%）。

所以设计成**一个应用、白帽优先、两边入口并存**，不做角色切换：

- Web3 里身份就是钱包地址，同一个地址既可以是项目方 admin，也可以是白帽收款人。按角色拆成两个应用，或者登录后先选身份，都是 web2 习惯。
- 侧边栏同时放"我托管的项目（Programs）"和"我的提交（Submissions）"两个分区，结构和 Lemma 的 Projects / Chats 完全一样（见 §6.2）。
- MVP 不接钱包，所以"我的"先退化成：Programs = 全部受保护项目（目前只有 1 个），Submissions = 后端记录的全部提交。接钱包之后再按 `admin == 钱包` 和 `payout == 钱包` 过滤，页面结构不变。
- Demo 和 pitch 的主角是白帽；项目方只在 pitch 里讲 20 秒（"接入只要一个暂停钩子"），外加一页静态接入指南。

## 4. 商业模式（只讲，不实现）

- **结算抽成**：每笔成功兑付的赏金，平台抽约 10%（参考 Immunefi 的模式，向项目方收）。在 `on_report` 里加一笔分账即可。
- **验证押金**：白帽提交时付一笔很小的验证费，覆盖 TEE 算力、防刷；验证通过则退还。
- **持续监控订阅**：工作流本来就是 cron 触发，可以周期性重跑已知攻击类、检查不变量，一旦可被打破就自动暂停。按月收稳定币，即"熔断器即服务"。
- 不碰保险牌照、不做资金池承保，平台只做验证与撮合。

## 5. 用户流程（按队友的实际实现）

### 5.1 项目方

1. 程序接入暂停钩子：`guardian` 字段 + `pause` 指令（演示用的 `vulnerable_vault` 已经带了）。
2. 调 `register(threshold, amount)`，把赏金转进赏金 PDA。程序会检查：调用者是 admin，金库 guardian 是赏金 PDA，金库未暂停，当前余额不低于阈值。
3. 想撤回：先 `request_cancel`，7 天后才能 `cancel`。等待期内赏金照样能被领取。

MVP 里这一步由队友的 `chain.ts init` 完成，前端只**展示**结果，不做创建表单。

### 5.2 白帽

1. 在首页看到被保护的金库、赏金金额、不变量。
2. 在本地构造攻击交易并用**自己的密钥**签名，不广播（演示里就是 `bun chain.ts attack-tx exploit`）。工作流开了签名校验，所以没法冒充 admin。
3. 在提交页粘贴收款地址和 base64 交易，点提交。
4. 在验证页看实时进度：模拟、测量、报告、结算。
5. 结果：赏金到账，金库已暂停，金库余额不变。

**时效限制**：交易用了 `recentBlockhash` 且关闭了替换，签好后大约 60 秒内必须完成模拟；报告生成后也要在 150 个 slot（约 60 秒）内上链。所以界面上要提示"生成后立刻提交"，后端拿到提交要马上跑。

### 5.3 系统内部（验证页的步骤就按这个画）

| 步骤 | 实际发生了什么 | 对应代码 |
| --- | --- | --- |
| 1 Submitted | 后端收到 `收款地址:交易`，写进临时 secret 文件 | `test.sh` 写 `SECRET_ATTACK_TX` |
| 2 Simulating | `cre workflow simulate`，工作流在 TEE handler 里运行 | `handlerInTee` |
| 3 Measured | `getBalance` 拿 pre，`simulateTransaction` 拿 post，判定谓词 | `SOLANA_JOURNAL pre= post= slot=` |
| 4 Reported | 96 字节报告：pre / post / slot / threshold / payout / vault | `SOLANA_REPORT=0x…` |
| 5 Settled | forwarder 提交 `on_report`：CPI 暂停金库 + 转赏金 | `chain.ts submit` + `status` |

## 7. 数据与接口

### 7.1 前端直接读链（只读，`@solana/web3.js`，经 TanStack Query）

| 账户 | 布局（小端） | 页面用途 |
| --- | --- | --- |
| 赏金 PDA，种子 `["bounty"]`，123 字节 | `0..32` admin、`32..64` forwarder、`64..96` vault、`96..104` threshold、`104..112` amount、`112` active、`113` claimed、`115..123` cancel_after | 赏金金额、不变量、状态 |
| 金库 PDA，种子 `["vault"]`，75 字节 | `0` paused、`2..34` guardian、`34..66` admin、`74` flash_open | 暂停状态、guardian 校验 |
| 金库 / 收款地址余额 | `getBalance` | 当前余额、结果页的余额对比 |

状态推导：`claimed=1` 为 Paid；`active=1` 且 `cancel_after>0` 为 Cancel pending；`active=1` 为 Active；其余为 Inactive。

### 7.2 薄后端（部署在 AWS，前端经 axios + TanStack Query 调用）

| 接口 | 作用 |
| --- | --- |
| `GET /api/config` | 返回 cluster、RPC、程序 ID、PDA 地址（来自 `proofs/launch.env`），前端不硬编码地址 |
| `GET /api/claims` | 提交列表，给侧边栏 Submissions 和赏金详情的 Submissions 分区用；只返回状态、收款地址、时间、结果数字 |
| `POST /api/claims` | 请求体 `{ payout, tx }`，返回 `{ claimId }`，立即开始跑 |
| `GET /api/claims/:id` | 当前阶段 + 已有结果（刷新页面时恢复） |
| `GET /api/claims/:id/events` | SSE 事件流 |

事件类型：`submitted`、`simulating`、`measured {pre, post, slot, threshold}`、`reported {reportHex}`、`settled {signature, paused, payoutDelta, vaultBefore, vaultAfter}`、`rejected {pre, post}`、`failed {stage, message}`、`log {line}`。

硬性要求：任何返回给浏览器的内容都不能包含攻击交易原文。`test.sh` 已经在做日志脱敏，后端照这个做。

**分工建议**：队友把 `test.sh` 的攻击段落拆成一个机器可读的脚本，例如 `script/claim.sh <payout> <txfile>`，每个阶段输出一行 JSON。你写 HTTP + SSE 外壳去调用它。两人之间的接口就是这些 JSON 行。

## 8. Demo 录屏脚本（约 2 分 30 秒）

1. BountyPage：介绍被保护的金库，4 张保护条件卡全部满圈（10 SOL 赏金、不变量、guardian、时间锁）（20 秒）
2. 终端：白帽在本地生成攻击交易并复制（15 秒）
3. 点 `Submit a finding` 进入 SubmitPage：粘贴后原文立刻变成密封胶囊，读一遍保密说明，点发送（20 秒）
4. ClaimPage：5 个阶段依次展开，测量胶囊显示 10 → 0.002 SOL，报告胶囊说明"离开飞地的只有这些"（60 秒）
5. 卡片变成 `Bounty paid: 10 SOL`，下方三格统计显示赏金到账、金库暂停、余额不变，点开浏览器交易（25 秒）
6. 回到 BountyPage：状态变成 `Paid`，金库 `Paused`，Submissions 分区多出这一条（10 秒）

加分项：开头先提交一笔"正常还款的闪电贷"，展示 `Rejected`，证明非攻击交易拿不到钱。
