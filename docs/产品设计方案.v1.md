> 时间：2026-10-06 18:25 SGT
> 基于队友仓库 ItsSunshineXD/2049Origins 的实际实现 + 前端骨架（frontend/）
> 第 9 节的三个决策已拍板

---

## 1. 一句话

把链上漏洞赏金变成**无需信任、自动结算**的协议：项目方把赏金和"什么算被攻破"一起锁进合约；白帽**私密**证明漏洞可被利用（攻击代码永不公开、永不上链）；证明一通过，合约在同一笔交易里把赏金打给白帽、并自动暂停出问题的合约。

可以类比成"Immunefi，但去掉了人工核保、谈判、KYC 和'相信对方会付钱'"。

---

## 2. 为什么必须上链（评委必问）

- **项目方不用被信任。** 赏金事先锁死，规则公开，兑付由合约执行，不是靠项目方良心。
- **白帽不用被信任。** 他不需要真的发动攻击、不需要转走资金再谈判。他只提交一份"可被利用"的证明。
- **赔付和暂停原子发生。** 验证通过的同一笔交易里完成赔付+暂停，中间没有人能插手。
- **抗审查、可组合。** 任何白帽无需许可即可参与，任何合约都能被保护。

这些承诺，只有智能合约 + 去中心化验证能给。普通 web2 后端做不到"不信任任何一方还能自动兑付"。

---

## 3. 产品形态

一个双边市场 + 一层自动风控：

- **需求侧（项目方）**：为自己的合约挂赏金，定义不变量（invariant），锁入 ETH。
- **供给侧（白帽）**：发现漏洞后，私密提交攻击代码，证明不变量可被打破。
- **中间的信任机器**：Chainlink CRE 机密工作流在 TEE 里预演攻击、验证谓词，产出 DON 签名报告；合约凭报告自动赔付 + 暂停。

两种运行模式（同一套合约+工作流）：
1. **赏金认领（本次 demo 主线）**：白帽针对某个挂了赏金的合约，私密提交一个具体 exploit。
2. **持续监控 / 自动熔断（路线图，cron 触发天然支持）**：工作流周期性重跑已知攻击类/检查不变量，一旦变得可被打破就自动暂停+赔付。队友当前实现就是 cron 触发，所以这条是"已经在底座里、只差包装"。

---

## 4. 两个角色的使用流程

### 4.1 项目方（Protocol）

1. 让自己的合约接入一个暂停钩子：一个 `pause()` + 一个 `guardian` 地址（把 guardian 设为赏金合约）。这是唯一的集成成本。
2. 在前端"创建保护"：选目标合约地址、设阈值（不变量，MVP = ETH 余额不得低于 X）、填赏金金额。
3. 钱包签一笔 `register`，赏金锁入合约。保护进入 Active。
4. 之后可随时 `cancel` 取回未被认领的赏金。

### 4.2 白帽（Whitehat）

1. 在前端浏览"赏金列表"，挑一个目标。
2. 本地写好/验证 exploit（给出 creation bytecode），在"私密提交"页粘贴 exploit + 填收款地址。
3. 前端把 exploit 加密后发给后端 → 后端注入 CRE 工作流的 secret → 触发 `cre workflow simulate`（在 TEE 里预演）。
4. 前端实时显示验证过程（飞地日志、journal 的 pre/post）。
5. 验证通过 → forwarder 提交报告 → 合约自动把赏金打到白帽收款地址、暂停目标合约。
6. 结果页展示：赏金到账交易、合约已暂停状态，附区块浏览器链接。

**关键诚实点：** 攻击代码只在 TEE 里被预演，不广播、不公开。前端要把这件事可视化地讲出来——这是整个产品的卖点。

---

## 5. 商业模式

- **主：结算抽成（take-rate）。** 每笔成功兑付的赏金，平台抽 X%（参考 Immunefi 的 ~10% 绩效费）。与成交量绑定，激励一致。合约里加一行分账即可（本次先不做，写进路线图）。
- **次：持续监控订阅。** 项目方按月付稳定币，开启 cron 模式的不变量监控 + 自动熔断。对应"真实收益 / 风控 SaaS"叙事。
- 不碰保险牌照、不碰资金池承保，保持轻资产：平台只做验证撮合。

## 6. 前端页面设计

> 约束：主舞台禁止 live demo，提交的是嵌在 slides 里的录屏。所以前端要"在录屏里好看、把机制讲清楚"，交互节奏要适合讲解。

沿用已迁移的 Lemma 骨架（灰底 + 240px 侧边栏 + 圆角主面板）。

### MVP 页面（必须跑通，按顺序）

1. **Bounties 列表（首页）**
   - 卡片列出每个保护：目标合约、阈值、赏金金额、状态（Active / Claimed / Paused）。
   - 顶部"连接钱包"。
   - 这是 demo 的起点和落点。

2. **Create Protection（项目方）**
   - 表单：目标地址、阈值、赏金金额。
   - 提交 = 钱包签 `register`。成功后回列表，新卡片出现。

3. **Submit Exploit（白帽）**
   - 选中某个 bounty 进入。
   - 文本框粘贴 exploit creation bytecode + 收款地址。
   - 显著提示："你的攻击代码会被加密，只在可信飞地内预演，永不公开、永不上链。"
   - 提交 → 进入验证页。

4. **Verification（验证过程，demo 高潮）**
   - 分步状态机：加密提交 → 飞地内预演 → 谓词校验（显示 pre/post 余额）→ DON 签名报告 → 链上结算。
   - 实时滚动飞地日志（后端 SSE 推送 `cre workflow simulate` 的输出，脱敏掉字节码）。

5. **Result（结果页）**
   - 大字显示：赏金已支付 / 合约已暂停。
   - 赔付交易链接、目标合约 `paused=true`、白帽余额变化，全部给区块浏览器链接。

### 砍掉 / 延后（主流程跑通前不碰）

- `cancel` 取回、分账抽成 UI、持续监控订阅页、多 exploit 类型、commit-reveal、Solana 结算镜像、暗黑模式、落地页营销。

## 7. 把前端接到队友后端的方式

前端无法直接跑 `cre workflow simulate`（那是 CLI）。需要一个**薄后端**（部署到 AWS）：

- `POST /api/claims`：收 exploit + payout + bountyId → 落地 secret、起本地 anvil 或连 Sepolia、跑队友的 `cre-demo.sh` 流程、执行 `onReport`。
- `GET /api/claims/:id/logs`（SSE）：把脚本输出流给前端验证页。
- 读链上状态（bounty 列表、paused、余额）：前端用 wagmi/viem 直连 RPC（NOWNodes 端点）。

录屏里这一整套可以真实跑通一遍。因为上台不是 live demo，只要录制时它能跑，就是"真的"。

## 8. 和之前"先暂停后验证"讨论的差异

队友选择了"验证 → 原子暂停+赔付"，没有链上 claim、没有押金。结论：**采用他的设计。** 它天然消除了恶意暂停（griefing）问题，不需要押金机制，合约更简单。遗留的信任点（TEE 硬件、报告提交时的抢跑窗口）写进 pitch 的 trust model + roadmap，坦诚说明。

**例外：exploit 自报 post 余额必须修，不能只写进 pitch。** 现在 `(pre, post)` 是白帽 exploit 构造函数自己 `return` 出来的，伪造一个直接返回 `(10 ETH, 0)` 的"exploit"就能领走赏金。修法：工作流不直接执行白帽的 creation code，而是包一层可信 harness 构造函数——先读 `vault.balance` 记为 pre，再带 value `CREATE` 白帽 exploit，然后再读一次 `vault.balance` 记为 post，最后 `return abi.encode(pre, post)`。依然只用一次 `eth_call`，合约侧不用改。
