# 修复：赏金判定可被伪造

## 问题

`onCronTrigger` 用 `eth_call` 执行未公开的 creation code，把返回值解码成 `(preBalance, postBalance)` 写进报告。`CreBounty.onReport` 只检查报告里的数字。一段不碰金库、只在构造函数里 `return abi.encode(10 ether, 0)` 的代码就能满足谓词，领走赏金并暂停目标。

本机 anvil 复现。金库存 10 ETH，阈值 1 ETH：

| creation code | 修复前 | 修复后 |
| --- | --- | --- |
| `AttackDeployer`（真实重入） | pre=10 post=0，通过 | pre=10 post=0，通过 |
| `FakeDeployer`（不碰金库，见本目录） | pre=10 post=0，**通过** | pre=10 post=10，拒绝 |

## 修复

飞地自己测量余额，不读 creation code 的返回值。

1. `preBalance`：`eth_getBalance(vault, block.number)`。
2. `postBalance`：一次 `eth_simulateV1`，基块是 `block.number`。同一个模拟块里两笔调用：
   - 未公开的 creation code。`from` 是没有任何角色的新地址 `0x1000…0001`，余额用 state override 注入。
   - 余额探针。state override 把 runtime code `0x6000353160005260206000f3` 放在 `0x2000…0002`，calldata 是 `abi.encode(vault)`。这段字节码是 `PUSH1 0 CALLDATALOAD BALANCE PUSH1 0 MSTORE PUSH1 32 PUSH1 0 RETURN`，返回值就是攻击执行之后的金库余额。
3. 攻击调用 `status != 0x1`，或者探针失败，直接抛错，不出报告。

报告编码、九个字段、`CreBounty.sol` 都不变。

## 改动

只有 `bounty-cre/workflow.ts`。本目录的 `workflow.ts` 是改好的完整文件，`0001-measure-vault-balance-in-enclave.patch` 是对应的 diff，二选一。

- `eth_call` 换成 `eth_getBalance` 加 `eth_simulateV1`。
- 删掉配置项 `caller`，模拟发送方改为常量 `SIM_SENDER`。原因：demo 里 `caller` 是部署者，同时是金库 admin。目标合约如果给特权角色留了提款路径，正常的特权操作也会满足谓词。`cre-demo.sh` 生成的配置里多出来的 `caller` 会被 zod 丢掉，不影响运行，可以顺手删。
- creation code 不再需要返回 `abi.encode(pre, post)`。`AttackDeployer` 现在的返回逻辑可以留着，工作流不读它。

## 已验证

- 本机 anvil 1.8.5，chain id 11155111。用同样的 RPC 序列跑了上表两行。两次模拟之后，链上金库余额仍是 10 ETH。
- 公共 Sepolia 节点 `ethereum-sepolia-rpc.publicnode.com`：`eth_simulateV1` 加 code override 的探针，读出的余额和 `eth_getBalance` 一致。
- `tsc --noEmit` 通过。依赖是仓库锁定的 `@chainlink/cre-sdk` 1.18.0、`viem` 2.34.0。

## 没验证，需要你跑

我这边没有 `cre` CLI 和 bun，没跑完整的 `cre workflow simulate`。

在仓库根目录：

```bash
git apply 0001-measure-vault-balance-in-enclave.patch
bash script/cre-demo.sh
```

期望最后一行是 `CRE_DEMO_OK`。

反例：把 `FakeDeployer.sol` 放进 `examples/fake/`。`cre-demo.sh` 的 `compile_creation` 里，源文件路径换成 `examples/fake/FakeDeployer.sol`，Python 片段里的合约名 `AttackDeployer` 换成 `FakeDeployer`。期望 simulate 失败，日志里有 `predicate failed pre=10000000000000000000 post=10000000000000000000`。

NOWNodes 的 Sepolia 节点是否支持 `eth_simulateV1` 还不知道，接之前测一下。不支持的退路是 `debug_traceCall` 加 `prestateTracer` 的 `diffMode`，从状态差里读金库余额。
